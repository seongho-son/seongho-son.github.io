## 배합과 환산 근거

설명란의 '오징어볶음 (2인분)' 재료 및 '오징어 볶음 만드는 법' 1–15번을 기준으로 작성했다. 원본 2인분을 왼쪽 1–2인분에, 정확히 두 배인 4인분을 오른쪽 3–4인분에 넣었다. 1인분은 왼쪽 전체의 절반이다. 별도 덮밥 배합은 이번 글에 포함하지 않았다.

## 조리 순서와 불확실성 처리

- 설명란 1–4: 내장·뼈·눈·입·단단한 빨판 제거, 껍질을 유지하고 몸통 약 1.5cm, 긴 다리는 반으로 자른다.
- 5–8: 대파 일부는 0.3cm 송송, 나머지는 1cm 어슷 썬다. 양파 1cm, 당근 0.4cm 두께·5cm 길이, 양배추 2–3등분, 고추 0.5cm 두께·3cm 길이.
- 대파는 재료표 ½대(50g)와 순서의 '1/3대 + 2/3대'가 문자 그대로는 맞지 않는다. 자막 손질 구간에서 준비한 대파를 나눠 파기름용과 마무리용으로 쓴다고 설명하므로, 재료표 총량을 유지하고 그중 ⅓·⅔로 나누는 해석을 채택했다. 본문에서 총량 기준임을 명시했다.
- 9–12: 식용유·송송 썬 대파로 파기름 → 대파가 노릇해지면 오징어 → 수분이 나오면 황설탕 → 진간장·마늘·고춧가루·고추장.
- 13: 양념이 뭉치면 강불에서 당근·양배추·양파·물 투입. 영어 자막 조리 후반은 약불에서 채소 수분을 내는 방법과 강불에서 물을 보태 양념을 푸는 방법을 비교한다. 게시물은 설명란의 후자를 채택했다.
- 14–15: 남은 대파·홍고추·청양고추·참기름을 섞고 접시에 담아 통깨로 마무리.
- 영어 자막 채소 손질 구간에서 양배추·당근·홍고추 생략 가능 안내를 확인했다. 기본 표는 모두 포함한 설명란 배합을 유지했다.
- 제공된 자막에는 타임스탬프가 없어 근거 구간을 내용으로 기록했다. 볶는 분 단위 시간과 파기름 단계의 고정 화력은 원본에 없어 만들지 않았다.

## 편집자가 추가한 정보

- 4인분 환산, 가정 계량 기준, 물기 제거와 이미 익은 건더기를 덜고 양념만 줄이는 방법, 4인분을 두 번 나누어 볶는 기준, 밥·상추 곁들이기는 편집자 안내다.
- 실용 팁은 수분 조절 / 분량·팬 크기 / 곁들이기의 서로 다른 각도다. 첫 문단 길이는 각각 213·200·208자로 모두 120–250자다. 첫 팁은 인스타 카드에서도 독립적으로 읽을 수 있다.
- instagram.hook은 26자이며 본문에서 2인분 물 45ml, 4인분 90ml로 답한다.
- 오징어의 두꺼운 부분까지 익었는지 확인하고 완성 후 바로 담는 안내는 편집자 덧붙임이다.
- 작성자 고정 댓글과 시청자 댓글은 확인하지 않았다. 댓글의 문구·반응·변형 팁을 사용하지 않았다.
- 직접 조리·시식 전이다. cooked, 평점, 열량, 임의 발행일·총 조리시간을 만들지 않았다.
- 썸네일 https://i.ytimg.com/vi/0CL9U_Se8Gs/maxresdefault.jpg 의 HTTP 200 응답과 1280×720 크기를 확인했다. 이미지 생성 없음.
- 기존 공용 템플릿의 인분 UI를 포함한 디자인·레이아웃은 요청대로 보존했다. 두 분량 데이터를 모두 제공한다.

## 최종 검증

- `npm run build` → `npm run verify:built` → `python3 .agents/skills/youtube-recipe-blog/scripts/audit_recipe.py --project . --slug paik-ojingeo-bokkeum` 모두 통과했다. 영상 링크 대체 후에도 같은 순서로 재실행했다.
- 홈 목록·상세·RSS·사이트맵·canonical·검색 title 연결을 확인했다. JSON-LD의 재료 16개와 조리 단계 5개가 데이터의 분량·문단과 정확히 일치한다.
- HEAD의 기존 dailyRecipes와 새 첫 항목을 제외한 배열을 deep equality로 비교해 정확히 1개 추가와 기존 콘텐츠 보존을 확인했다. 전체 영상 ID 중복 없음, 신규 cooked 없음, hook과 팁 길이 기준 충족. 최종 diff와 원본 배합·호출 흐름을 검토했다.
- 독립 Chrome headless의 320·390·1440px에서 홈 → 새 상세 이동, 새 상세·기존 김치찌개의 가로 넘침 없음, 재료·순서 앵커를 확인했다. 현행 템플릿에는 별도 바로가기 버튼이 없어 앵커 이동으로 검사했다. 모바일 전체 화면도 직접 읽고 검토했다.
- 실제 부모 페이지에서 공식 youtube-nocookie iframe을 요청 차단 없이 로드하고 '동영상 재생' 버튼을 눌렀다. '로그인하여 봇이 아님을 확인하세요'가 표시됐고 video paused=true/currentTime=0/readyState=0이었다. 이 글만 embed:false로 설정해 현행 템플릿의 원본 썸네일·영상 링크로 대체했다.
- 대체 후 세 화면 폭에서 썸네일 실제 로드, 원본 링크, 인분 전환, 계량 안내 표시(모바일은 펼치기), 가로 넘침 없음과 JSON-LD 일치를 재확인했다.
- 직접 조리·Google 공식 리치 결과 테스트는 수행하지 않았다. 이미지 생성·커밋·푸시·배포 없이 로컬 산출물만 작성했다.
