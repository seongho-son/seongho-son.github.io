## 설명란 근거와 환산

[재료]와 한국어 [만드는 법] 1–5번을 기준으로 했다. 인분 표기는 없어 원본 라면 1개를 1인 식사로 보는 편집상 기준을 사용했다. 1–2인분 열은 2인 식사(원본 2배), 3–4인분 열은 4인 식사(원본 4배). 혼자 먹을 때는 왼쪽 열 전체를 절반으로 줄인다.

| 재료 | 원본 | 1–2인분 | 3–4인분 |
|---|---|---|---|
| 순한맛 라면 | 1개 | 2개 | 4개 |
| 동봉 분말수프 | ½–⅔봉 | 1–1⅓봉 | 2–2⅔봉 |
| 동봉 건더기수프 | 1봉 | 2봉 | 4봉 |
| 대파 | 약 ⅓대(30g) | 약 ⅔대(60g) | 약 1⅓대(120g) |
| 물 | 1½컵(270g) | 종이컵 3컵(540ml) | 종이컵 6컵(1,080ml) |
| 황설탕 | 1큰술(12g) | 2큰술(24g) | 4큰술(48g) |
| 고추장 | 1큰술(20g) | 2큰술(40g) | 4큰술(80g) |

수프 양은 설명란 조리법과 자막의 동봉 수프 설명에서 확인했다. 별도 구매 재료가 아니며 라면에 포함된다. 물만 1g≈1ml로 환산해 180ml 종이컵으로 표기했다. 숟가락은 원본 단위와 무게를 병기하고 가정 밥숟가락의 오차를 안내했다. 고형 재료의 무게를 부피로 바꾸지 않았다.

## 조리 순서와 자막 확인 범위

1. 한국어 설명란: 대파를 송송 썬다.
2. 물·분말수프·건더기수프·설탕·고추장을 풀며 끓인다.
3. 끓으면 면을 넣는다.
4. 면이 완전히 풀리면 대파를 넣고 약 1분 더 끓인다.
5. 물이 졸고 면이 익으면 불을 끈다.

제공된 영어 자막에는 타임스탬프가 없으므로 시간을 지어내지 않았다. 중반 시연에서는 면을 넣은 다음 설탕·고추장을 넣으며 시점이 자유롭다고 설명한다. 게시물은 한국어 설명란 순서를 채택하고 차이를 본문에 밝혔다. 영어 설명란의 almost cooked 대신 한국어 설명란의 '면이 완전히 풀어지면'을 기준으로 했다.

자막 후반에서 화력과 냄비 크기에 따라 면보다 물이 먼저 줄 수 있으며 물을 보충해 익히라고 안내한다. 자막의 대파는 선택 재료지만 재료표는 설명란의 대파 포함 배합으로 작성했다. 마지막 면부터 담고 양념을 올리는 순서도 자막에서 확인했다. 고정된 불 세기·총 조리시간을 원본 정보로 만들지 않았고 제목의 '1분'을 총 조리시간으로 쓰지 않았다.

## 편집자 추가와 한계

- 인분 환산, 가정 계량 안내, 양념을 덜어 식혀 맛보기와 추가 간 조절, 두 번 나누어 끓이는 방법, 별도 채소 곁들이기는 편집자 안내다. 면보다 물이 빨리 줄 때 불을 낮추는 안내도 편집자 덧붙임으로 표시했다.
- 팁은 간 조절 / 분량별 도구·시간 / 곁들이기 세 각도로 188·187·196자. 첫 팁은 인스타 팁 카드로 사용 가능하다. hook은 24자로 본문에서 분말수프 양을 답한다.
- 작성자 고정 댓글과 시청자 댓글은 확인하지 않았다. 댓글 반응·문구·변형 팁을 사용하지 않았다.
- 직접 조리·시식 전이다. cooked, 평점, 열량, 임의 발행일, 총 조리시간 없음.
- 썸네일 https://i.ytimg.com/vi/6e-IbuuD6ZU/maxresdefault.jpg 는 curl 정상 응답과 sips 1280×720 크기를 확인했다. 자체 이미지 생성 없음.
- 기존 공용 템플릿의 인분 선택 UI는 이번 요청의 기존 디자인·레이아웃 변경 금지에 따라 보존했다. 양쪽 분량 데이터는 모두 제공한다.

## 최종 검증

- `npm run build` → `npm run verify:built` → `python3 .agents/skills/youtube-recipe-blog/scripts/audit_recipe.py --project . --slug paik-rabokki` 통과. 플레이어 대체 뒤에도 세 검사를 같은 순서로 재실행했다.
- HEAD의 기존 dailyRecipes와 새 배열의 첫 항목을 뺀 데이터를 deep equality로 비교해 기존 콘텐츠 보존과 정확히 1개 추가를 확인했다. 전체 영상 ID 중복 없음, 신규 cooked 없음, hook 40자 이하, 검색 title의 레시피 자동 삽입, JSON-LD 재료 7개·조리 단계 4개의 본문 일치를 확인했다.
- 독립 Chrome headless의 320·390·1440px에서 홈·새 상세·기존 김치찌개 상세의 가로 넘침 없음. 모바일 전체 화면을 직접 읽고 검토했다.
- 공식 youtube-nocookie iframe을 실제 부모 페이지에서 요청 차단 없이 로드했다. 처음 검사에서는 현재 플레이어의 버튼 클래스 변경으로 재생 클릭이 수행되지 않았고, 이후 원본 iframe을 지정해 실제 '동영상 재생' 버튼을 눌렀다. '로그인하여 봇이 아님을 확인하세요'가 표시되며 paused=true/currentTime=0/readyState=0이었다. 새 글만 embed:false로 바꿔 기존 템플릿의 썸네일·원본 링크로 대체했다.
- 직접 조리와 Google 공식 리치 결과 테스트는 수행하지 않았다. 이미지 생성·커밋·푸시·배포 없이 로컬 산출물만 작성했다.
