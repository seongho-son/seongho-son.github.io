## 순서와 편집 범위

1. 설명란 1–4번: 닭 사방 2cm, 양파 반 갈라 0.3cm 채썰기, 대파 0.3cm 어슷썰기, 달걀 가볍게 풀기, 간장·설탕·맛술 소스 섞기.
2. 5–7번: 기름 두른 팬에 닭 껍질을 아래로 굽기, 기름이 나오면 가장자리에 양파 올려 누르기, 닭이 노릇하면 함께 볶기. 중불은 자막에서 확인했다.
3. 8–9번: 닭 표면이 하얗게 되면 소스와 물을 넣고 끓이기, 훈연멸치가루 넣고 뚜껑 덮기.
4. 10–11번: 닭이 완전히 익으면 달걀과 대파 넣고 뚜껑 덮어 익히기, 밥 위에 얹기.

표면이 하얗다는 것과 중심까지 익은 것을 구분하는 안내, 달걀 완숙 권장은 편집자가 덧붙였다고 표시했다. 자막은 반숙/완숙을 취향으로 설명한다. 원본에 고정된 가열 시간이 없어 분 단위 시간을 추가하지 않았다.

팁은 소스 수분·간 조절(203자), 여러 인분을 나눠 굽기(205자), 닭가슴살 대체 시 조절(219자)로 각도가 다르다. 닭가슴살 대체 가능은 원본 자막에도 나오지만 구체적인 가정용 조절 안내는 ‘편집자 제안’으로 분리했다. 첫 팁은 인스타 카드에 들어갈 구체적인 실패 방지 안내다. hook은 22자로 양파 투입 시점을 묻고 본문 2단계에서 답한다.

## 확인 범위와 미디어

- 작성자 고정 댓글과 시청자 댓글은 확인하지 않았다. 댓글 문구·경험·반응은 채택하거나 만들어내지 않았다.
- 직접 조리·시식하지 않았고 `cooked` 필드, 별점, 열량, 총 조리시간, 임의의 공개일은 추가하지 않았다.
- 썸네일: https://i.ytimg.com/vi/du9q1BldDHU/maxresdefault.jpg — curl HTTP 200, Pillow로 1280×720 확인. Python urllib의 로컬 인증서 오류는 curl의 정상 TLS 요청으로 재확인했다.
- 이미지 생성·단계 이미지는 없다. 공식 플레이어 및 브라우저 확인 결과는 아래에 기록한다.

## 로컬 검증

- `npm run build` → `npm run verify:built` → `python3 .agents/skills/youtube-recipe-blog/scripts/audit_recipe.py --project . --slug paik-chicken-deopbap` 모두 통과했다. 홈 목록·RSS·상세·사이트맵·canonical·애드센스·팁·인분·단계 연결을 확인했다.
- 이전 HEAD 데이터와 deep equality로 비교해 기존 항목이 동일하고 새 글만 1개 증가했음을 확인했다. 전체 영상 ID 중복 없음, 신규 cooked 없음, hook 40자 이내, 검색 title에 ‘레시피’ 자동 삽입을 확인했다.
- JSON-LD의 재료 11개와 조리 단계 4개가 입력 데이터와 일치한다. 원본 배합의 2배/4배 환산과 팁 분량을 직접 대조했다.
- 독립 Chrome headless에서 320·390·1440px 홈·새 상세·기존 김치찌개 상세의 가로 넘침 없음, 홈에서 새 상세 이동 및 재료 영역 존재를 확인했다. 390px 전체 화면 캡처를 직접 검토했다.
- 현행 공용 재료 UI는 인분 선택형이고 재료 바로가기 앵커 링크가 없다. 스킬의 오래된 병렬 표/바로가기 설명과 다르지만 사용자 지시대로 기존 디자인·레이아웃을 보존했다. 첫 브라우저 검사에서 존재하지 않는 앵커 선택자가 실패해 현재 템플릿에 맞는 검사로 수정했다.
- 직접 조리와 Google 공식 리치 결과 테스트는 수행하지 않았다. 커밋·푸시·배포하지 않았으며 공개 발행을 주장하지 않는다.

- 공식 youtube-nocookie 플레이어는 실제 부모 페이지에서 정상 로드됐으나 재생 클릭 뒤 “로그인하여 봇이 아님을 확인하세요”가 나타났다. video 상태 paused=true/currentTime=0/readyState=0으로 재생 불가를 확인해 새 글만 `embed:false`로 변경, 기존 템플릿의 공식 원본 썸네일 링크로 대체했다. 요청 차단으로 만든 오류가 아니며 재생 성공을 주장하지 않는다. 변경 후 세 가지 필수 검증과 화면 검사를 다시 수행했다.
