## 순서 대조

1. 원본 1–3번: 김치를 가위로 잘게 자르고, 대파·청양고추는 송송, 소시지는 최대한 얇게 편 썬다 → 글 1단계.
2. 원본 4–5번: 손질한 재료를 섞은 뒤 고춧가루·설탕·부침가루·물을 넣어 뭉침을 푼다 → 글 2단계.
3. 원본 6–9번: 달군 팬에 기름을 넉넉히 두르고 반죽을 얇게 편다. 익기 시작하면 팬을 돌려 기름을 안쪽까지 보내고, 가장자리 윗부분이 익기 시작할 때 뒤집는다. 뒤집은 뒤에도 팬을 돌리며 부치고 충분히 익으면 다시 뒤집어 마무리한다 → 글 3단계.

신김치가 아닐 때 양조식초를 넣을 수 있다는 원본 괄호 안내는 팁에만 반영했다. 분량 미제시이므로 정량 배합을 만들지 않았다. 불 조절·나눠 부치기는 편집자 팁으로 명시했다. 원본 설명란은 정확한 불 세기와 조리 시간을 주지 않으므로 시간·칼로리·평점 구조화 데이터는 만들지 않는다.

## 최종 검증

- `npm run build` → `npm run verify:built` → `python3 .agents/skills/youtube-recipe-blog/scripts/audit_recipe.py --project . --slug paik-kimchi-jeon` 통과. 영상 대체와 문구 수정 후 같은 순서로 재실행했다.
- Chrome/Playwright에서 390px·1440px·320px 목록 썸네일 실제 로드, 제목 클릭 상세 이동, 4장 이미지 디코딩(1536×1024), 인분별 재료 표시, 만드는 순서 바로가기, 가로 넘침 없음을 확인했다. 세 화면의 재료 영역 스크린샷도 직접 검토했다. 기존 김치찌개는 390px·1440px에서 제목과 가로 넘침 없음을 확인했다.
- 공식 youtube-nocookie iframe을 실제 로컬 부모 페이지에서 요청 차단 없이 로드했고, 원본 제목·썸네일이 표시됐다. 재생 버튼 클릭 후 “로그인하여 봇이 아님을 확인하세요”가 표시되고 video.currentTime=0, paused=true, readyState=0이었다. 이 환경의 재생 제한으로 판단하며 모든 사용자에게 재생이 불가하다고 일반화하지 않는다. 스킬에 따라 새 글의 embed=false로 원본 썸네일 링크를 사용하고, 공개 원본 주소로 이동하도록 했다.
- 원본 영상 페이지 내용 확인과 영상 재생 성공은 구분한다. 직접 조리 및 Google 공식 리치 결과 테스트는 수행하지 않았다. 로컬 감사 통과를 Google 승인으로 표현하지 않는다.
- 총 24개 글, slug 경로 24개와 영상 ID 24개가 각각 고유하다. 기존 23개에 정확히 1개 추가. 기존 추적 파일은 more-recipes.js의 import와 배열 연결 2줄 외에 변경되지 않았다. 커밋·푸시·배포하지 않았다.
