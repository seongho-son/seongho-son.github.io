# 인스타 2주 운영

기간: 2026-10-31–2026-11-13, Asia/Seoul. 기존 launchd는 매일 15시에 실행하고 스크립트 내부에서 발행일을 판정한다.

- 시험 기간 인스타 발행일: 10/31, 11/2, 11/4, 11/6, 11/8, 11/10, 11/12. 하루 최대 1개, 총 7개 예정. 실패한 날의 글을 다음 비발행일에 몰아 올리지 않고 다음 발행일 대기열에서 처리한다.
- 11/14부터는 기존 매일 15시 대기열 발행으로 돌아간다. 블로그의 기존 이틀 간격 13시 발행은 유지한다.
- 게시된 글과 게시 여부가 불확실한 글을 재게시하지 않는다. 기존 publish.py의 중복/불확실 상태 검사를 유지한다.
- 블루/옐로우를 기존 대기열 순서대로 번갈아 사용한다. 원본 썸네일, 재료 두 인분표, 전체 조리 순서, 재료 강조를 유지한다. AI 이미지는 생성하지 않는다.
- 표지에는 해당 글이 답하는 실용 질문/포인트를 사용한다. 기존 대기열 8개는 growth-plan.json에 지정했다. 새 블로그 글은 instagram.hook으로 전달한다.
- 조리 순서 뒤에 기존 블로그 tips의 첫 문단을 팁 카드로 담고 마지막 카드에는 저장/팔로우 안내와 간단한 질문을 넣는다. 핵심 레시피를 사이트 방문 뒤로 숨기지 않는다.
- 댓글 출처가 확인되지 않은 내용을 댓글 팁이라고 부르지 않는다. 과거 삭제한 캡션 하단 고정 면책문을 복구하지 않는다. 원본 채널·영상 출처는 유지한다.

## 측정

`~/Automation/instagram-library/growth-metrics.csv`와 `growth-review.md`가 예약 실행 때 갱신된다. 게시 시간·주소·색상은 실제 manifest 기록에서 채운다. 인사이트 연결은 없으므로 도달·저장·공유·프로필 방문·팔로우는 게시 48시간 후 인스타에서 확인한 값만 입력한다. 빈칸은 미확인이며 0으로 처리하지 않는다. 제공되지 않는 지표는 비워둔다. 재실행해도 입력한 값과 메모는 보존한다.

11/6과 11/13에 같은 관찰 기간의 저장/도달·공유/도달·팔로우/프로필 방문 비율을 비교한다. 표본이 부족하면 성장 효과를 단정하지 않는다. 알림·인사이트 자동 수집·자동 전략 변경은 구현 범위에 포함하지 않는다.
