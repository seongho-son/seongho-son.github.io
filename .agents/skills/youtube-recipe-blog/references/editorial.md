# 사용자가 선택한 글쓰기와 계량

## 메뉴 선정

- 메뉴를 추천할 때는 자취하는 사람이 적은 재료와 기본 도구로 쉽게 만들 수 있는 한 끼를 우선한다. 여러 반찬을 차리는 가정식 구성으로 편중하지 않는다.
- 재료 구입 부담, 한 팬·한 냄비 사용, 혼자 먹을 양으로 줄이기 쉬운지를 본다. 선택 고명과 대체 제안은 원본 필수 재료와 구분한다.
- 사용자가 유지하거나 제외한 메뉴를 그대로 반영한다. 인분 표시는 현재 사이트 패턴을 유지하되 원본 1인분과 환산 기준을 본문에 명확히 적는다.

## 제목과 말투

검색 대상 메뉴명과 해당 레시피를 선택할 구체적인 이유를 담는다. 사용자가 제목을 직접 지정하면 그대로 사용한다.

- 형식은 `<채널 인물> <요리명>, <한 줄 포인트>`(예: `백종원 떡볶이, 쌀떡이냐 밀떡이냐 고민이면 둘 다!`). 쉼표 앞은 사람들이 검색하는 요리명 그대로 쓴다. 검색용 `<title>`은 사이트가 쉼표 앞에 '레시피'를 붙여 자동으로 만든다(`src/data/search-title.js`).

- 어떤 요리에도 붙일 수 있는 상투적인 문구로 제목·도입·마무리를 채우지 않는다. ‘오늘 저녁은 이걸로’, ‘오늘 뭐 먹지’ 같은 문구는 사용하지 않는다. 확인한 인기, 조리 특징, 사용자가 제공한 경험 등 이 레시피에만 해당하는 내용을 쓴다.
- 다른 채널의 레시피를 백종원 레시피라고 부르지 않는다.
- ‘완벽한 가이드’, ‘핵심 요약’, 장황한 효능·역사 소개, 모든 제목 앞의 이모지, 똑같은 박스 섹션 반복을 피한다.
- 도입은 짧게, 해당 레시피를 가져온 구체적인 이유부터 쓴다.
- 목록 소개와 본문 도입은 제목을 이어받아 독자가 공감할 상황이나 궁금한 점을 짧게 건넨다. 조리법 요약으로 쓰지 않는다. 재료·계량·투입 순서·불 조절·팁은 해당 본문에 두고, 소개를 설명하려고 뒤에 덧붙이지 않는다. 사용자가 지정한 소개 문구는 그대로 유지한다. 댓글 반응이나 자료 수집 과정도 소개의 중심으로 삼지 않는다. 메뉴명만 바꿔도 통하는 상투적인 도입은 다시 쓴다.
- 실제로 만들지 않았으면 “먹어보니”, “남편이 두 그릇 먹었어요”, “여러 번 해본 결과”를 쓰지 않는다. 글이 영상 정리임을 밝힌다.
- 감정 표현은 실제 내용에 대한 짧은 반응과 함께 쓴다. 댓글에서 발견한 의외의 반응, 조리 중 헷갈리는 순간, 취향이 갈리는 지점처럼 맥락이 있는 곳에 말투·문장 호흡·이모지를 함께 조절한다. 음식 이모지만 붙이거나 정해진 위치·개수를 채우지 않는다. 실제로 하지 않은 조리 경험을 감정 표현으로 꾸미지 않는다.
- 소제목은 동사로: “대파를 송송 썰어요”, “끓기 시작하면 불을 줄여요”.
- 조리 설명은 맛과 결과에 영향을 주는 행동·분량·불 세기·두께에 집중한다. 당연한 동작 설명을 본문에 그대로 옮기지 않는다.
- 블로그와 인스타 카드는 단계 설명 속 **재료 이름만** 자동으로 굵게(주황) 표시한다. 재료표의 이름(또는 그 안의 낱말)을 본문에서도 그대로 쓴다. 예: 재료표가 `떡볶이떡`인데 본문에 `떡`만 쓰면 표시되지 않으니 재료표를 `떡`으로 하거나 본문에 `떡볶이떡`을 쓴다. 본문에 `<strong>` 강조는 넣지 않는다(표시 단계에서 지워진다).

## 원본에 없는 정보 (애드센스·검색 품질 기준)

이 사이트의 글은 유튜브 레시피를 정리한 글이다. 영상에 이미 있는 재료·순서만 옮기면 애드센스와 Google이 "다른 곳에 이미 있는 내용(가치 낮은 콘텐츠)"으로 판단하기 쉽다. 그래서 모든 글에 원본 영상만 봐서는 얻기 어려운 정보를 담는다. 아래 1~3은 필수, 4는 실제로 찾았을 때만 넣는다.

1. **인분 환산**: 원본 분량을 기준으로 1–2인분 / 3–4인분 두 열을 계산하고, 원본이 몇 인분 기준인지와 어떻게 환산했는지를 `portionNote`(또는 같은 역할의 안내 문단)에 적는다.
2. **종이컵·밥숟가락 계량**: 원본의 g·ml·계량컵을 집에서 바로 쓸 수 있는 종이컵(180ml)·밥숟가락·개 단위로 옮기고, 기준을 `measureNote`에 적는다. 환산 근거가 없는 재료는 원본 단위를 유지하고 그 사실을 밝힌다(아래 "분량과 단위" 기준).
3. **실용 팁 2개 이상(3개 권장)**: 이 요리에서 실제로 헷갈리거나 실패하기 쉬운 지점을 짚는 팁을 `tips`에 넣는다. 팁 하나는 본문 120–250자로, 왜 그런지와 구체적인 행동(분량·불 세기·시간·상태)을 함께 쓴다. 팁마다 아래에서 **서로 다른 각도**를 고른다. 같은 각도를 두 번 쓰지 않는다.
   - **실패·간 조절**: 짤 때·싱거울 때·탈 때·물이 생길 때 등 이 요리에서 흔한 실패와 되돌리는 법.
   - **재료 대체**: 재료가 없을 때 바꿀 수 있는 것. 원본 배합과 분리하고 문장에 "편집자 제안"이라고 밝힌다. 재료표를 바꾸지 않는다.
   - **분량 조절 시 시간·불**: 3–4인분으로 늘리거나 1인분으로 줄일 때 냄비·팬 크기, 불 세기, 끓이는 시간이 어떻게 달라지는지. 시간을 무조건 배수로 늘리지 않는다.
   - **남은 음식 보관·데우기**: 보관 용기, 냉장 기간, 다시 데우는 방법과 식감 변화.
   - **곁들이기**: 이 요리와 어울리는 밥·반찬·마무리(볶음밥, 면 추가 등)와 그 이유.
   영상 내용을 다시 요약한 문단이나 어떤 요리에도 붙일 수 있는 일반론("간은 취향껏")은 팁으로 치지 않는다. 자동 검사(`audit_recipe.py`)는 `tip-N` 섹션 2개 이상, 팁 본문 합계 300자 이상을 요구한다. 글자 수만 채운 팁은 통과해도 발행하지 않는다.
4. **시청자 댓글 팁**: 댓글에서 실제로 확인한 유용한 경험이 있으면 해당 단계나 팁에 곁들인다(아래 "곁들이는 댓글 팁과 재미" 기준). 없으면 채우지 않는다.

- 팁과 대체 재료도 지어내지 않는다. 일반 조리 상식에 기댄 팁은 "편집자가 덧붙인 내용"으로 구분해 쓰고, 원작자의 배합처럼 보이게 하지 않는다.
- **정직성**: 직접 만들지 않았으면 "해보니", "여러 번 만들어 보니" 같은 경험을 팁에 쓰지 않는다. 일반 조리 원리로 설명한다. 재료 대체는 항상 "편집자 제안"으로 표시한다.
- **식품 안전은 보수적으로**: 보관 기간은 짧은 쪽으로 쓴다(조리한 국·찌개·볶음은 식혀서 냉장 1–2일 안). 상온 보관을 권하지 않고, 고기·달걀·해산물은 속까지 익히고 다시 데울 때 한 번 충분히 끓이도록 쓴다. 근거 없는 냉동 기간·효능을 만들지 않는다.
- **직접 조리 기록(`cooked`)**: 데이터의 선택 필드 `cooked`(직접 만든 날짜·메모·사진)는 사이트 주인이 실제로 만들어 본 뒤에만 채운다(`docs/cook-verification.md`). 자동 생성기·에이전트는 이 필드를 절대 만들거나 채우지 않는다.
- 출처 영역(`sourceNote`)에는 원본에서 가져온 것과 편집자가 환산·덧붙인 것을 구분해 적는다.
- 집필을 마치면 "이 글에서 영상에 없는 정보는 무엇인가"를 스스로 확인한다. 1~3 중 하나라도 비어 있으면 발행하지 않고 채운다.

## 곁들이는 댓글 팁과 재미

레시피 자체로 글을 완성한 뒤, 실제로 읽은 댓글에 유용한 팁이나 재미있는 반응이 있으면 짧게 곁들인다. 댓글은 글의 기획 근거나 필수 콘텐츠가 아니다. 별도 조사 분량을 채우거나 댓글을 중심으로 도입·조리 설명을 다시 쓰지 않는다. 원작자가 댓글에 제공한 재료·순서는 시청자 반응과 달리 원본 레시피 자료로 취급한다.

- 원작자의 배합과 시청자의 변형을 구분한다. 댓글의 팁으로 기본 재료표를 조용히 바꾸지 않는다.
- 해당 단계나 맛 조절 문단에 자연스럽게 녹인다. 모든 글에 같은 댓글 코너나 항목 수를 강제하지 않는다.
- 일부 경험은 ‘한 시청자는’, 여러 건에서 확인한 반응은 그 범위에 맞게 표현한다. 좋아요 수나 조회수를 맛의 보증으로 삼거나 전체 여론처럼 일반화하지 않는다.
- 채택한 댓글의 링크 또는 ID, 확인일, 요지를 기존 출처 문서에 남긴다. 댓글을 읽지 못했거나 유용한 정보가 없으면 꾸며 채우지 않고 확인 범위를 기록한다.

## 분량과 단위

재료표 열은 `재료 | 1–2인분 | 3–4인분`. 탭·인분 선택기는 만들지 않는다.

- 액체: **종이컵 n컵**. 물, 육수 모두 단위를 생략하지 않는다.
- 조미료: 큰술·작은술 등 이해할 수 있는 숟가락 단위. 큰술은 사이트 관례상 밥숟가락으로 안내하되, 원본의 표준 계량스푼 15ml와 가정 숟가락이 같다고 단정하지 않는다.
- 채소·두부·달걀: 개·대·모처럼 자연스러운 단위.
- 김치: 신뢰할 만한 근거가 있으면 반 포기·¼포기 등. 포기 크기에 따라 달라서 맞지 않으면 **종이컵 n컵**으로 쓴다. 재료명에 “썰어서 n컵”을 반복하지 말고 표 위 안내에 담는 법을 설명한다.
- 컵은 **180ml 종이컵**. 원본의 한 컵이 200ml/240ml라면 이를 그대로 같은 컵 수로 옮기지 않는다.
- 고형 재료 1g=1ml로 환산하지 않는다. 원본에 부피·개수 정보가 없으면 믿을 만한 환산 근거를 확보한다. 확보 못 한 경우 불확실성을 표시하고 사용자에게 확인을 요청한다. 보기 편한 숫자를 위해 배합을 지어내지 않는다.
- 원본 인분/분량에서 기준 배합을 잡고 두 분량을 계산한다. 원본 인분이 명시되지 않으면 편집상 추정이라는 사실을 기록한다.
- 두 배 분량에서 조리 시간을 무조건 두 배로 만들지 않는다. 소금·간장·매운 재료는 조절 팁과 구분한다.

## 출처와 설명의 정확성

- 원본 배합·순서, 편집상 인분 환산, 추가 팁을 구별한다.
- 영상 설명과 자막이 다르면 원문 근거를 확인하고 채택한 기준을 밝힌다.
- 직접 조리하지 않았으면 출처 영역에 검증 전이라고 명시한다.
- 재료표·순서·구조화 데이터 간 재료와 분량을 맞춘다.

## 검색 전략

- 종이컵·인분은 사용성 장점이다. 검색량이 큰 키워드로 자동 간주하지 않는다.
- 검색 데이터가 필요하면 실제 도구에서 엔진·지역·조회일·단위를 확인한다. 네이버 수치를 Google 수치로 전용하지 않는다.
- 짤 때·신맛 등 해당 요리의 문제 해결 팁은 우선 본문에 통합한다. 비슷한 글을 키워드별로 양산하지 않는다.
- 기본 구조화 데이터는 Recipe. 원작자에게 사이트 글의 저자 지위를 임의 부여하지 않는다.
- 정확한 조리 시간·평점·칼로리를 모르면 생략한다. 숫자를 채워 리치 결과 자격을 꾸미지 않는다.
- 임베드가 자동 검색 썸네일/순위를 보장한다고 말하지 않는다.
